### Added

- `gjc doctor` diagnoses configuration, permissions, installation, plugins, and services, and repairs a fixed catalogue of nine actions under `--fix`. Diagnosis and `--dry-run` are strictly read-only: they never write product state, fetch, execute a plugin, or start a service. Every repair names one exact action and one exact target, and the two gates are independent: `--allow-risk` authorizes a risk class and `--yes` only skips interactive confirmation, so neither substitutes for the other or bypasses integrity, ownership, or occupancy verification. Artifact-replacing repairs additionally require an operator-supplied `--ref` and `--sha256` matched against recorded provenance.
- `gjc doctor --fix --repair service.restart-owned` restarts the SDK broker and Discord, Slack, and Telegram daemons through each owner's prepare/commit protocol. Restart success requires kernel-confirmed predecessor absence and a genuinely different successor process incarnation; matching PIDs are not accepted as proof.

### Fixed

- `gjc doctor --fix` now refuses to plan a repair when a selected collector timed out or was cancelled and is therefore still writing to the shared diagnosis context. The action is reported as `blocked` with reason `incomplete_diagnostics` and exit 3, while the diagnosis still shows everything that was collected.
- The `gjc doctor` supervisor no longer writes to the worker's stdin after the worker has settled. A confirmation prompt could resolve after a deadline, SIGINT, or crash had already torn the child down, and the resulting write surfaced as an EPIPE/`ERR_STREAM_DESTROYED` that took the parent process with it. The protocol channel is now a one-way latch closed on `exit`, `close`, and stdin `error`, and every residual race is contained as a `worker_channel_closed` outcome instead of an exception.
- A `gjc doctor` worker report whose `selection` envelope is missing or malformed is now classified as `worker_report_invalid` instead of throwing. The plausibility gate only validated shallow fields while the protocol handler dereferenced `selection.repair` and `selection.targetId` directly, so a malformed report raised a `TypeError` inside the readline listener rather than degrading to a bounded report.
- Marketplace plugin sources are now contained by canonical path, not by a lexical check that can silently degrade. `pathIsWithin` falls back to comparing unresolved paths whenever `realpath` fails, so a catalog-supplied plugin directory that is a dangling or looping symlink out of the marketplace root passed the containment gate and was then followed by the existence probe. Relative and `git-subdir` sources now canonicalize both the root and the candidate before use, and an existing entry that cannot be canonicalized is refused as an untrusted source.
- Catalog-controlled marketplace plugin sources can no longer inject git options or dispatch a git remote helper. A `url`/`git-subdir` source must be an https/http/git/ssh/file URL, a `user@host:path` remote, or an absolute local path; values starting with `-` (`--upload-pack=<cmd>`) and `<helper>::<args>` remote-helper URLs (`ext::sh -c ...`) are refused. A `github` repo and the `owner/repo` shorthand must match a plain slug, and a `git-subdir` path must be relative and must not start with `-`. `git.clone` also passes `--` before the URL so no caller can reintroduce the option-parsing hole.
- `gjc doctor --fix` now refuses journal-backed repairs on Windows before any mutation instead of failing mid-action. The crash-recovery journal implements its durability primitives only under `#[cfg(unix)]`, so `config.set-validated`, `mcp.set-startup-policy`, `permissions.restrict-owned-config`, `install.repair-managed-link`, `plugin.quarantine-selected`, and `service.detach-owned-stale-artifact` are blocked with `unsupported_platform` on win32 and the limitation is documented in `gjc doctor --help`. Diagnosis and `--dry-run` are unaffected on every platform.
